Streams one flight's status. Each update's `data` has the same fields as [Get flight status](/api-reference/flights/status); `at` is when the message was built. See [Connect](/api-reference/live/connect) for the message format.

## Parameters

<ParamField body="callsign" type="string" required>
  ICAO callsign of the flight, e.g. `DAL1277`. Case and spacing are ignored.
</ParamField>

```json
{"action": "subscribe", "subscription_topic": "flight_status", "params": {"callsign": "DAL1277"}}
```

## Updates

The first update is the flight's current status, the same as `GET /api/v0/flights/status` with `at` set to now, sent right after `subscribed`. `status` is `null` when the flight had no substantive communication on available channels in the last hour.

After that, each transmission on an available channel that is attributed to the flight is evaluated as it is processed, and a new update is sent when it changes the status. Readbacks, check-ins, sign-offs, and transmissions that repeat the current status do not send an update. Use `status_at` to order updates.

<Warning>
  Statuses are written by a language model from transcripts and can contain mistakes. Check important details against the transcripts from `GET /api/v0/transcripts?callsign=...`.
</Warning>

## Billing

Each status sent is charged as one `flight_status_update`, at \$0.12. The first status is charged when you subscribe, unless its `status` is `null`, and again each time you subscribe, including after a reconnect. See [Pricing](/pricing) and [Billing](/concepts/billing).

## Refusals

The subscription is refused when `callsign` is missing, when the charge for the first update is refused, or when the flight status could not be loaded; retry that last case later.
